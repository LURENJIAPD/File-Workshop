# M05 文件目录模块开源方案调研

> 调研日期：2026-08-10  
> 对应模块：模块 05 文件目录  
> 结论：本模块不直接引入第三方代码，只参考成熟文件协作系统的目录、空间、权限边界思路。

## 1. 调研目标

模块 05 属于文件管理系统核心能力，但当前开发范围只覆盖目录事实层，不涉及对象存储、版本内容、扫描、预览和索引。调研重点不是寻找可直接复制的代码，而是验证以下设计是否符合成熟系统经验：

1. 文件夹和文件共享统一命名空间；
2. 目录项身份与具体内容版本分离；
3. 文件操作入口必须复用统一权限判定；
4. 移动和重命名必须处理路径缓存、继承权限和循环关系。

## 3. 对本模块的影响

本次实现采纳以下设计取向：

- 统一命名空间：Folder 和 Document 共享 `namespace_entries`，用数据库唯一索引保证同父目录名称冲突。
- 身份与内容分离：Document 可以先创建稳定身份，真实版本、对象 Key 和容量扣减由后续模块接入。
- 权限入口统一：目录列表、详情、创建、重命名、移动都调用模块 04 最终授权服务。
- 路径缓存可重建：移动和重命名会更新受影响子树路径；真实事实仍以 `parent_folder_id` 和数据库约束为准。
- 存储解耦：模块 05 不接触 SeaweedFS/S3，不创建对象存储专属字段，避免在未搭建对象存储集群时阻塞基础目录开发。
