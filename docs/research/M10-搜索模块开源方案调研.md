## 2. 对 File Workshop 的取舍

本项目采用以下规则：

1. 搜索入口先返回 PostgreSQL 元数据候选，不依赖对象存储、预览、OCR、AI 或外部搜索集群；
2. 候选查询只作为“可能结果”，返回前必须逐项调用权限模块执行 `READ_METADATA` 最终复核；
3. 当前周期仅搜索 `ACTIVE` 目录项，避免回收站、清理中和已清理资源进入普通搜索；
4. 统一使用 `page/pageSize`，不新增 cursor/limit 别名；
5. `total` 当前只表示本页可见数量，不做跨页精确总数，避免昂贵统计和无权资源数量泄露；
6. 全文、OCR 和语义搜索未启用时，响应 `degraded=true`，前端可明确提示“当前为元数据搜索”。

实现：

- `GET /api/v1/search`；
- 按关键词匹配名称、规范化名称、扩展名和分类；
- 按 `spaceId/entryType/extension/classification/createdByUserId/updatedFrom/updatedTo/metadataKey/metadataValue` 筛选；
- PostgreSQL 候选查询、稳定排序和分页；
- 逐项 `READ_METADATA` 最终权限复核；
- 搜索结果复用 `DirectoryEntry` 响应结构，并返回 `matchedFields/indexStatus/source/degraded`；
- OpenAPI、sqlc、统一 API 文档、开发计划和应用层测试。
