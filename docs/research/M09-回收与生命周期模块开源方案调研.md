> 日期：2026-08-10  
> 结论：本周期不直接引入第三方回收站模块源码；参考成熟网盘系统“回收站元数据独立记录、恢复前冲突校验、永久清理异步化、保留策略阻断清理”的通用做法，按 File Workshop 已冻结数据库、权限和 Outbox 模型自行实现。

## 2. 对 File Workshop 的取舍

本项目采用以下规则：

1. 回收站事实以 `recycle_items` 为入口，目录生命周期以 `namespace_entries.lifecycle_status` 为准；
2. 删除进入回收站时不设置 `namespace_entries.deleted_at`，避免违反当前数据库约束；只有进入 `PURGING/PURGED` 时才写入 `deleted_at`；
3. 删除文件夹时递归标记活动子树为 `TRASHED`，并将源资源共享标记为 `SOURCE_UNAVAILABLE`；
4. 恢复前校验原空间、目标父目录、目标名称冲突、资源状态、`rowVersion` 和权限；
5. 永久清理先标记为 `PURGING` 并写入 Outbox，实际对象清理由后续 Worker 处理；
6. 资料保全存在时阻断永久清理，避免生命周期策略绕过冻结要求；
7. 查询和写操作都通过权限模块最终判定，不因回收站列表暴露无权资源。

## 3. 当前周期范围

实现：

- `POST /api/v1/entries/{entryId}/trash`：进入回收站；
- `GET /api/v1/recycle-bin`：分页查询回收站项目；
- `POST /api/v1/recycle-bin/{recycleItemId}/restore`：恢复到原位置或指定父目录；
- `POST /api/v1/recycle-bin/{recycleItemId}/purge`：发起永久清理，标记 `PURGING` 并写入 Outbox；
- 回收默认保留期 90 天；
- 删除时共享源不可用标记、空间安全纪元递增和 Outbox 事件写入；
- 恢复重名冲突、根目录禁止删除、资料保全阻断清理和幂等键冲突单元测试。

暂缓：

- 自动过期扫描和批量清理 Job；
- 资料保全创建/解除接口；
- 归档/冷存储生命周期策略；
- 对象存储真实删除、版本对象引用计数和孤儿对象扫描；
- HTTP 集成测试和真实大目录性能测试。
