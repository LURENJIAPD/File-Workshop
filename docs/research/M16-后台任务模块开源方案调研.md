# M16 后台任务模块开源方案调研

> 调研日期：2026-08-10  
> 对应模块：模块 16 后台任务  
> 当前周期：Outbox Worker、background_jobs 基础调度与管理员运维接口

## 1. 调研目标

当前项目已经在身份、用户、组织、权限和文件目录模块中把业务事件写入 `outbox_events`，数据库设计也已冻结 `background_jobs` 作为通用后台任务事实表。本周期目标是先补齐可靠消费、基础调度和最小运维地基，而不是引入完整消息队列或复杂调度平台。

调研重点：

1. PostgreSQL 是否适合作为 V1.0 的轻量队列领取机制；
2. Go Worker 如何安全停止并避免 Goroutine 泄漏；
3. 是否需要立即引入 Kafka、RabbitMQ、NATS、Temporal、Asynq 等外部组件；
4. 是否可以先用现有 PostgreSQL 表支撑管理员查询积压、查看失败原因和受控单项重试。

## 2. 官方资料结论

| 来源 | 结论 | 对本项目影响 |
|---|---|---|
| PostgreSQL 官方 `SELECT` 文档 | `FOR UPDATE ... SKIP LOCKED` 会跳过无法立即锁定的行，官方说明它不适合一般一致性读取，但可用于多个消费者访问“队列表”以避免锁竞争 | Outbox 领取使用 `FOR UPDATE SKIP LOCKED`，并配合状态、租约和稳定排序 |
| Go 官方 `context` 文档 | `Context.Done()` 用于通知取消，`WithTimeout` 可限制单次处理时长 | Worker 主循环、处理器超时和停止信号统一走 `context.Context` |
| Go 官方 `os/signal` 文档 | `NotifyContext` 可在收到系统信号时取消 Context，并要求及时调用 `stop` 释放资源 | `cmd/worker` 用 `signal.NotifyContext` 接收 Ctrl+C / SIGTERM，进入优雅关闭流程 |

参考来源：

- PostgreSQL `SELECT` / Locking Clause：https://www.postgresql.org/docs/current/sql-select.html
- Go `context` package：https://pkg.go.dev/context
- Go `os/signal` package：https://pkg.go.dev/os/signal

## 3. 开源组件评估

| 方案 | 优点 | 暂不引入原因 |
|---|---|---|
| Kafka/RabbitMQ/NATS | 高吞吐、跨服务订阅、独立事件保留 | V1.0 技术选型已冻结为 PostgreSQL Outbox + Go Worker；当前无压测证据证明数据库轮询成为瓶颈 |
| Temporal | 工作流能力强、重试和可观测完善 | 运维和建模成本明显超出当前阶段；会改变架构形态，需要 ADR |
| Asynq/Redis 队列 | Go 生态友好、任务队列能力现成 | Redis 不能成为业务事实唯一来源；本项目已有 PostgreSQL `background_jobs/outbox_events` 事实表 |
| 自研 PostgreSQL Outbox/Job Worker | 依赖少、与现有事务事实一致、可渐进扩展，直接复用已冻结的 `outbox_events/background_jobs` | 需要严格控制范围，先做领取、租约、重试、死信、处理器注册和最小运维接口，不做完整调度平台 |

## 4. 本周期采纳方案

- 业务事实和 Outbox 继续由各模块在同一 PostgreSQL 事务写入。
- Worker 只领取已注册处理器支持的 `event_type`，避免在审计等消费者未实现时吞掉历史事件。
- `background_jobs` 作为通用任务事实表，当前只实现入队、认领、执行、续租、成功、失败、死信和受控重试框架，不接真实文件处理任务。
- 领取条件覆盖：
  - 到期 `PENDING`；
  - 到期 `FAILED`；
  - 租约过期的 `PROCESSING`。
- 成功后标记 `PUBLISHED`。
- 可重试失败标记 `FAILED` 并写入 `next_retry_at/last_error_*`。
- 永久失败或重试耗尽标记 `DEAD`。
- 管理员 REST API 提供 Outbox/Job 分页查询与 `FAILED/DEAD` 单项重试，普通用户禁止访问。
- `cmd/worker` 独立启动，使用 `context` 和系统信号优雅停止。

## 5. 未纳入本周期的内容

- 不实现完整调度平台、任务 DAG、周期任务、优先级动态调整或跨服务编排；
- 不实现 Job 取消、批量重放、批量死信管理、告警闭环和人工处理工作流；
- 不消费未注册事件；
- 不引入 MQ 或 Redis 队列；
- 不执行 Hash、扫描、预览、索引、生命周期或审计归档的具体业务处理器。
