# M06 文件传输与存储适配基线调研

日期：2026-08-10  
模块：06 文件传输与存储  
范围：对象存储协议、Go SDK、适配层边界和 Windows 本地开发基线。

## 1. 背景

项目已通过 ADR-021 冻结对象存储方向：

- 对象存储协议：S3 Compatible API；
- 默认实现：SeaweedFS S3 Gateway；
- Go SDK：AWS SDK for Go v2；
- 业务代码只能依赖项目内 Object Storage Interface。

当前用户明确说明 Linux/SeaweedFS 环境尚未搭建，因此本周期不实现完整上传会话和真实对象存储兼容性测试，只先完成可在 Windows 本地验证的适配层、禁用模式、配置和健康检查。

## 2. 参考资料

| 来源 | 类型 | 结论 |
|---|---|---|
| AWS SDK for Go v2 S3 官方示例：<https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/go_s3_code_examples.html> | 官方文档 | AWS SDK v2 提供 S3 客户端、预签名和 Multipart API，是 Go 端访问 S3 兼容协议的合理基础 |
| SeaweedFS Amazon S3 API Wiki：<https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API> | 官方仓库文档 | SeaweedFS 通过 S3 API Gateway 暴露 S3 兼容接口，业务侧应保持 S3 语义而非 Filer/Volume/Needle 内部结构 |
| 项目 ADR-021：`docs/adr/ADR-021-对象存储默认实现调整为SeaweedFS.md` | 项目架构决策 | 明确禁止业务代码依赖 SeaweedFS 私有结构，数据库不保存产品私有字段 |
| 数据库设计说明第 7 章 | 项目权威数据库设计 | `storage_objects/upload_sessions/upload_parts` 已按 S3 兼容和上传会话设计，当前不新增或改名字段 |

## 3. 方案选择

采用：

```text
业务模块
  ↓
internal/platform/objectstorage.Client
  ↓
S3 adapter based on AWS SDK for Go v2
  ↓
S3 Compatible API
  ↓
SeaweedFS S3 Gateway / enterprise S3
```

本周期交付：

- `objectstorage.Client` 项目内接口；
- `DisabledClient`，用于当前未搭建对象存储的本地开发；
- `S3Client`，封装 AWS SDK for Go v2 的 S3 Multipart、预签名、HeadObject 和健康检查；
- `FILE_WORKSHOP_OBJECT_STORAGE_*` 环境变量；
- `objectStorage` 健康检查在禁用时显示 disabled，启用时执行 Bucket 可访问性检查。

暂不交付：

- `upload_sessions/upload_parts` 控制面事务；
- 上传 REST API；
- 真实 SeaweedFS 兼容性测试；
- Range 下载、对象元数据完整兼容性测试；
- 孤儿对象清理。

## 4. 风险与边界

1. AWS SDK v2 是必要新增依赖，但业务代码不得直接散落调用 SDK；只允许平台适配层引用。
2. 当前没有真实对象存储环境，不能宣称 Multipart、预签名上传、Range 下载已通过真实兼容性验证。
3. 数据库字段仍以数据库设计说明为准；本周期不新增 Migration。
4. 禁用模式不是 mock 成功，不会伪造上传完成；调用对象存储操作会返回 `ErrDisabled`。
5. 启用其他 S3 兼容实现前，必须验证 Multipart、预签名、Range、对象元数据、错误映射和路径风格。
