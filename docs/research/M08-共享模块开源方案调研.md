# M08 共享模块开源方案调研

> 日期：2026-08-10  
> 结论：本周期不直接引入第三方共享模块源码，仅参考成熟网盘系统的共享 API 语义，按 File Workshop 既有数据库与权限模型自行实现。

## 1. 参考对象

| 项目/文档 | 可参考点 | 不直接复用原因 |
|---|---|---|
| Nextcloud OCS Share API | 支持创建、更新、撤销、到期时间和权限位；公开链接默认权限收敛 | PHP/Nextcloud 应用架构与本项目 Go 模块化单体差异大；权限位模型与本项目动作白名单不同 |
| ownCloud OCS Share API | 用户/组/公开链接共享、到期时间和角色/权限更新语义 | 与 Nextcloud 同源体系，API 兼容思路可借鉴，但不能直接适配本项目数据库 |
| Seafile Share Links API | 下载链接、密码、过期时间和共享链接列表 | Seafile 基于资料库/路径模型，本项目基于稳定 Document/Folder ID 和统一授权入口 |

## 2. 对 File Workshop 的取舍

本项目采用以下规则：

1. 共享是独立访问来源，不写入普通 ACL；
2. 共享动作仅允许 `READ_METADATA`、`PREVIEW`、`DOWNLOAD`、`WRITE_CONTENT`；
3. `READ_METADATA` 是共享动作必选项；
4. 创建共享不能扩大创建者自身没有的权限；
5. `LINK` 共享只返回一次明文 `shareToken`，数据库仅保存 SHA-256 摘要；
6. 普通文件授权入口只接入 `USER` 和 `ORGANIZATION` 共享；`LINK` 必须通过共享打开接口校验 token；
7. 外部匿名链接默认关闭，本周期不实现匿名访问；
8. `SPACE` 目标共享需要同步创建 `shared_entries` 和命名空间引用，本周期暂缓，避免半成品引用。

## 3. 当前周期范围

实现：

- 创建 `USER`、`ORGANIZATION`、`LINK` 内部共享；
- 查询我创建的共享；
- 查询共享给我的用户/组织共享；
- 查询共享详情；
- 修改共享动作、期限和是否允许继续共享；
- 撤销共享；
- 打开共享并写入 Outbox 事件；
- 权限模块接入有效 `USER`/`ORGANIZATION` 共享作为最终授权允许来源。

暂缓：

- `SPACE` 目标共享和 `shared_entries` 可见引用；
- 匿名外部链接；
- 链接密码哈希；
- 分享访问后的真实下载/预览数据面；
- 大规模共享列表性能压测。
