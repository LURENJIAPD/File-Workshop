# FE-WebOS 工作台开源参考

> 整理日期：2026-08-14  
> 适用范围：前端可切换 WebOS 工作台产品形态调整  
> 结论：仅参考交互结构，不直接引入源码或依赖。

## 1. 调研目标

项目负责人确认希望 File Workshop 增加类操作系统桌面工作台，并支持与传统布局切换。本次调研用于确认 WebOS 工作台是否适合作为前端 Shell，以及是否存在可复用开源方案。

## 2. 参考项目

| 项目 | 许可证与维护状态 | 可参考内容 | 当前结论 |
|---|---|---|---|
| daedalOS：<https://github.com/DustinBrett/daedalOS> | GitHub 显示 MIT license；持续作为浏览器桌面环境项目维护 | 桌面、任务栏、启动器、多应用窗口和浏览器内桌面体验 | 可参考交互，不直接引入；其定位偏个人桌面/作品系统，和企业文件管理权限、审计、数据事实边界不同 |
| Vue-Window-Manager：<https://github.com/umaxiaotian/Vue-Window-Manager> | GitHub 显示 MIT license；Vue 3 窗口管理组件 | Vue 组件窗口、拖拽、父容器内窗口管理 | 前端启动时可再评估是否引入；当前先不冻结依赖，避免为了 Shell 过早增加耦合 |
| GitHub WebOS / Web Desktop Topic | 项目质量差异较大 | 常见桌面元素：Dock、开始菜单、窗口层级、动态壁纸、快捷方式 | 仅作 UI/UX 灵感来源，不能直接证明企业级可用性 |

## 3. 采用策略

1. WebOS 作为前端 Shell，不作为后端产品形态；
2. 传统布局继续保留，用户可切换；
3. WebOS 不复制业务页面，不新增业务 API；
4. 业务组件仍按模块组织，Shell 仅承载窗口、启动器、任务栏和通知；
5. 明暗主题、权限状态、加载/错误/空状态、无障碍和移动端回退必须统一考虑；
6. 前端实际开发前，再对当前 `frontend/` 模板和候选窗口管理依赖做一次许可证、维护状态、依赖安全和适配成本评估。

## 4. 不直接复用的原因

- 大部分 WebOS 项目偏作品展示、玩具系统或个人桌面，不具备企业权限、审计和文件生命周期语义；
- 直接引入完整 WebOS 项目会带来路由、状态、主题、窗口生命周期和依赖栈冲突；
- File Workshop 的核心价值是文件管理、权限、审计和可治理生命周期，WebOS 只能服务这些能力，不能反过来支配业务模型；
- 当前前端尚未正式开工，过早冻结窗口管理依赖会降低后续模板适配灵活性。

## 5. 后续评估点

前端启动时至少评估：

- 是否自行实现轻量 Window Manager；
- 是否引入 Vue Window Manager、WinBox 类库或等价组件；
- 窗口拖拽和缩放的无障碍替代操作；
- 多窗口同资源缓存失效；
- 上传中心、预览窗口、搜索窗口和审计窗口的状态隔离；
- 移动端和低性能设备回退策略。
