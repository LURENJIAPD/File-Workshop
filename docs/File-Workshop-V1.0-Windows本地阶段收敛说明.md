# File Workshop V1.0 Windows 本地阶段收敛说明

> 文档版本：V1.0  
> 文档状态：阶段收敛基线  
> 最近更新：2026-08-14  
> 适用范围：在尚未搭建 Linux 服务器、SeaweedFS S3 Gateway、预览/OCR/全文搜索/AI 等外部运行环境前，对 Windows 本地可完成工作的边界进行冻结说明。

## 1. 结论

Windows 本地阶段可以收敛，不应继续无限扩展后台小接口或控制面细节。

当前阶段已经完成了大量不依赖真实对象存储和 Linux 服务的后端基础能力，包括身份、用户、组织、权限、文件目录、上传控制面、版本与锁基础、共享基础、生命周期元数据、PostgreSQL 元数据搜索、审计查询与完整性、后台任务调度和运维管理。

后续继续在 Windows 本地开发时，原则上只做以下三类工作：

1. 修复已发现缺陷；
2. 补齐当前接口文档、开发计划、运行说明和测试说明中的明显缺口；
3. 做不依赖对象存储、文件内容、Linux 服务或外部组件的轻量验证。

除非项目负责人明确指定，否则不再为了“继续开发”而新增更多边缘运维接口。

## 3. 当前不应在 Windows 本地继续硬做的事项

这些事项不是“未努力”，而是缺少必要运行环境或外部组件。如果现在继续开发，容易产生假闭环、伪实现或需要日后大面积返工。

| 范围 | 暂缓原因 | 解锁条件 |
|---|---|---|
| 模块 06 上传完成、下载和 Range | 需要真实 S3 Compatible API 验证 Multipart、ETag、预签名、Range 和对象元数据 | Linux/SeaweedFS S3 Gateway 可用，并配置测试 Bucket、凭据和网络访问 |
| 模块 07 真实版本生成与下载 | 依赖模块 06 上传完成后写入 `storage_objects` 和 `document_versions` | 上传完成闭环可用 |
| 模块 08 共享下载、预览和匿名外链真实体验 | 依赖下载/预览和更完整的外链策略 | 模块 06/12 具备真实数据面 |
| 模块 09 真实对象清理和最终 `PURGED` 收敛 | 依赖对象存储删除、引用核验和孤儿对象处理 | SeaweedFS/S3 可用，且上传/版本事实链完整 |
| 模块 10 真实全文、OCR、外部索引和 `INDEX` 处理器 | 依赖文件内容读取、文本提取、预览/OCR 或外部搜索组件 | 文件版本和对象读取链路可用，搜索组件选型和环境明确 |
| 模块 11 审计导出、归档、WORM 和归档下载 | 依赖对象存储或归档介质 | 对象存储和归档策略可用 |
| 模块 12 预览 | 依赖文件内容读取、转换工具、安全隔离和资源限制 | 对象存储可读，预览运行环境和隔离策略确认 |
| 模块 13 WebDAV | 需要客户端兼容测试、锁语义与上传下载真实链路 | 文件上传/下载/锁闭环可用，并确认目标客户端矩阵 |
| 模块 14 SMB 迁移 | 需要 SMB 源端、网络、凭据、安全和迁移验证环境 | Linux/迁移节点、测试 SMB 共享和权限映射样本可用 |
| 模块 15 AI 与 Agent | 需要 V1.0 范围、模型/Workflow/向量或 RAG 方案确认 | 文件内容处理链路、AI 方案和权限审计边界确认 |

## 4. Windows 本地阶段剩余只建议做的收尾项

如果继续停留在 Windows 本地，建议只保留以下低风险收尾，不再开大功能：

1. 当前 OpenAPI、统一 API 接口文档和实现的全量一致性复核；
2. `.env.example`、README、启动说明、数据库导入说明和测试说明的最终校对；
3. 对已完成模块补少量缺失的应用层测试或 HTTP 集成测试；
4. 明确数据库 Migration 与已手工导入 SQL 的关系，避免后续环境重建时混淆；
5. 建立 Linux/SeaweedFS 阶段启动清单。

这些收尾可以提升确定性，但不会新增重大业务边界。

## 5. Linux/SeaweedFS 阶段建议启动顺序

Linux 和 SeaweedFS S3 Gateway 可用后，建议按以下顺序恢复开发：

1. 验证对象存储连接：Bucket、凭据、预签名 PUT/GET、Multipart、ETag、Range、错误码映射；
2. 完成模块 06 上传提交：登记 `upload_parts`，校验分片，写入 `storage_objects` 和 `document_versions`；
3. 完成模块 06 下载和 Range：生成短期下载凭证，记录下载审计意图；
4. 回接模块 07：上传完成创建真实版本，写入锁 Token/fencing 校验；
5. 回接模块 09：实现 `LIFECYCLE_PURGE` 真实处理器、引用核验、对象删除和 `PURGED` 收敛；
6. 回接模块 10/12：先做文本/PDF/图片等最小可用预览与索引处理器，再考虑 OCR、全文引擎和语义搜索；
7. 再进入 WebDAV、SMB 迁移和 AI/Agent。

## 6. 阶段完成判定

Windows 本地阶段满足以下条件即可视为收敛：

- 当前代码在 Windows 本地通过 `go test ./...`、`go vet ./...` 和 `git diff --check`；
- 所有已实现接口已同步 OpenAPI 和统一 API 接口文档；
- 开发计划已明确哪些模块是当前边界完成，哪些模块因环境暂缓；
- 不存在为了绕开对象存储、文件内容或 Linux 依赖而伪造成功状态的代码；
- 后续 Linux/SeaweedFS 启动顺序明确。

本说明形成后，除非项目负责人明确要求继续某个收尾项，否则 Windows 本地阶段不再主动扩展新功能。
