# ADR-022：前端支持可切换 WebOS 工作台

## 状态

接受。

## 背景

File Workshop 原前端定位偏企业后台与文件管理页面，适合快速开发和表单/表格/树形控件场景。项目负责人现在确认希望增加 WebOS，也就是为用户提供类操作系统桌面的工作台体验，并且要求支持切换。

制造业文件管理存在多窗口并行场景：文件列表、预览、版本、搜索、上传队列、共享、任务和审计经常需要同时打开。桌面式工作台可以降低频繁跳转成本，但如果把 WebOS 做成唯一入口，会增加开发复杂度、移动端适配和无障碍成本。

## 决策

V1.0 前端增加“可切换工作台模式”：

1. 默认保留传统企业后台/文件管理布局；
2. 新增 WebOS 工作台布局，提供桌面、任务栏、启动器、可拖拽/缩放窗口、多窗口、窗口最小化/最大化/关闭、快捷入口和通知区域；
3. 用户可以在个人偏好中切换传统布局和 WebOS 布局；
4. 同一业务页面必须复用同一套路由、权限、OpenAPI 客户端、组件和状态，不为 WebOS 复制第二套业务实现；
5. WebOS 仅是前端交互壳层，不新增后端领域模型，不改变数据库结构，不改变权限、审计、分页和 API 契约；
6. 移动端、低性能设备或无障碍场景可以默认回退传统布局；
7. 明暗主题必须同时覆盖传统布局和 WebOS 布局。

## 架构约束

- WebOS 窗口承载业务页面或业务组件，但业务权限仍由服务端最终判定；
- WebOS 不保存服务端业务事实，只保存用户界面偏好、窗口状态、最近打开应用等客户端状态；
- 客户端状态使用 Pinia 管理，服务端数据仍使用 TanStack Vue Query；
- 页面组件按系统模块组织，WebOS 只提供 Shell、Window Manager、Launcher 和 Dock/Taskbar；
- 不允许绕过 Vue Router、OpenAPI 客户端或权限模块；
- 不允许因为桌面体验而暴露对象存储 Bucket、Object Key、签名密钥或内部路径；
- 多窗口打开同一资源时，必须处理版本冲突、锁状态、上传状态和缓存失效。

## 实现建议

前端分层建议：

```text
frontend/
├── src/
│   ├── app-shell/
│   │   ├── classic/
│   │   └── webos/
│   ├── modules/
│   │   ├── files/
│   │   ├── search/
│   │   ├── shares/
│   │   ├── audit/
│   │   └── background/
│   ├── router/
│   ├── api/
│   ├── stores/
│   └── design-tokens/
```

WebOS 首批应用建议：

- 文件管理器；
- 搜索；
- 上传中心；
- 共享中心；
- 回收站；
- 预览窗口；
- 版本历史；
- 后台任务；
- 审计中心；
- 个人设置。

## 开源参考结论

本次仅参考 Web Desktop / WebOS 类项目的交互结构，不直接引入源码。调研记录见 `docs/research/FE-WebOS工作台开源参考.md`。后续若实际采用窗口管理、拖拽或虚拟化组件，必须重新核对许可证、维护状态、依赖安全和适配成本。

长期参考重点：

- Web Desktop 项目的桌面、窗口、任务栏和启动器交互；
- 成熟文件管理系统的文件列表、预览、分享和上传队列体验；
- Element Plus 等组件库在复杂后台和可访问性方面的基础能力。

## 影响

正面影响：

- 多任务文件处理更自然；
- 更贴近制造业用户熟悉的桌面文件管理心智；
- 预览、搜索、上传、版本和审计可以并行展示；
- 传统布局仍保留，降低学习和实现风险。

成本与风险：

- 前端 Shell 复杂度上升；
- 多窗口状态、焦点、快捷键、层级、响应式和无障碍需要额外测试；
- WebOS 如果做得过重，会拖慢前端开发效率；
- 移动端不适合完整 WebOS，需要自动回退或简化模式。

## 验证要求

- 传统布局和 WebOS 布局均可登录、退出、刷新会话；
- 用户切换布局后偏好可恢复；
- WebOS 下多窗口打开文件列表、预览、搜索和上传中心不互相污染状态；
- 明暗主题在两种布局下都可用；
- 键盘可访问性和焦点可见；
- 权限撤销后，已打开窗口不能继续展示越权内容；
- Playwright 覆盖布局切换、窗口打开/关闭、搜索打开文件、上传中心和权限拒绝。

## 备选方案

1. 仅传统后台布局：开发最快，但多任务体验较弱；
2. WebOS 作为唯一入口：体验统一，但风险和开发成本过高；
3. 可切换双布局：兼顾效率、体验和风险控制，因此采纳。
