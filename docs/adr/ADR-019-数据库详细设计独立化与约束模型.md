# ADR-019：数据库详细设计独立化与约束模型

> **状态：** 已接受  
> **日期：** 2026-08-05  
> **决策范围：** PostgreSQL 逻辑模型、物理约束、ID、时间类型、权限引用、审计分区、幂等、任务租约与法定保留

## 背景

原主设计文档第 18 章同时承担业务架构和数据库表结构，表结构仍存在多项无法直接进入首版 Migration 的问题：

- 实体主键列使用通用 `id`，类型保持 `UUID/ULID` 待选；
- 具体时刻使用裸 `TIMESTAMP`；
- 文件与文件夹分表，无法约束同目录跨类型重名；
- 权限、共享和保留使用不可建立外键的 `type + id`；
- Audit 分区键未进入主键和链唯一约束；
- Legal Hold 被建模为策略布尔值和文件状态；
- 幂等只在上传会话局部存在，Agent Confirmation 无事实表；
- Outbox 和后台任务缺少租约恢复字段；
- 配额只有使用量缓存，没有并发预留机制。

仓库尚无已发布数据库 Migration 和生产数据，可以在首版建库前修正，不承担兼容迁移成本。

## 决策

1. 将数据库详细设计从主设计文档移出，建立 `docs/File-Workshop-V1.0-数据库设计说明.md` 作为数据库结构唯一权威来源。
2. PostgreSQL 实体 ID 使用原生 `uuid`，由 Go 侧生成 UUIDv7；主键列使用语义化 `<entity>_id`。
3. 所有具体时刻使用 `TIMESTAMPTZ`，自然日期使用 `DATE`。
4. 建立 `namespace_entries` 统一文件夹、文件和共享引用的目录名称唯一性。
5. 权限、共享和保留事实使用类型化外键或统一命名空间引用；审计事件允许保存无外键历史快照。
6. Lifecycle、Availability 和 Legal Hold 正交建模；Legal Hold 使用独立、可多条并存、可审计的事实表。
7. 新增统一幂等记录、Agent Confirmation、配额预留、Refresh Token 家族、可恢复任务租约和配置修订历史。
8. Audit 按日期分区，分区键进入主键和链序号唯一约束；应用与数据库角色均禁止业务更新和删除审计事件。
9. Permission Actions、Share Actions 和 Admin Capabilities 使用受约束明细表，不使用未约束 JSONB 或不透明位图。
10. 首版 Migration 直接实现新模型，不保留旧字段别名、双写层或兼容视图。

## 结果

正向影响：

- 数据库能够直接保护名称、版本、权限引用、法定保留和分区唯一性等关键不变量；
- 权限撤销、任务恢复、幂等重试、配额并发和 Token 重放有明确持久化事实；
- 主设计文档专注业务与架构，数据库文档可以独立演进并接受 Schema 评审；
- 当前无 Migration，首版采用不会产生数据回填和兼容窗口。

代价与风险：

- 表数量和约束触发器数量增加，首版 Migration 与集成测试工作量上升；
- 统一命名空间和类型化权限列需要更明确的 Repository 查询；
- UUIDv7 生成、规范化算法、分区管理和约束触发器必须形成固定工具与测试；
- 数据库文档、Migration、sqlc 和 OpenAPI 相关字段必须在同一变更中同步。

## 被否决方案

- 继续在主设计文档中维护数据库章节：容易与业务章节混杂并重复演进。
- 保留通用 `id` 与 `UUID/ULID` 待选：不能形成可执行首版 Schema。
- 仅在 Service 中检查多态权限外键和目录重名：数据库可被并发、Bug 或维护脚本写入不一致事实。
- 使用单一文件状态表达隔离、归档、回收和法定保留：状态维度互相覆盖，无法表达多条 Hold。
- 为所有动作引入消息队列：V1.0 继续使用 PostgreSQL Outbox + Worker，避免不必要组件和分布式事务。

## 实施与验证

- 首版 Goose Migration 按数据库设计说明第 17 章顺序建立；
- 使用专用本地 PostgreSQL 随机临时数据库验证空库创建、升级、约束、并发、分区和恢复；具备 Docker/CI 环境时可选用 Testcontainers 提供等价隔离；
- 在真实量级数据上验证 Namespace、权限、Audit 和 Worker 查询计划；
- 任何偏离本 ADR 的结构变更必须更新 ADR、数据库设计说明和风险分析。
